GitHub Setup Instructions

Field Projects (FinTech Capstone Course)

This page walks through everything you need to do, from creating a GitHub account through submitting your repository link at the end of the semester. (Some of you may recall a GitHub feature called "Classroom" from other courses — GitHub is discontinuing it, so this semester you'll set up your project repository yourself, which is actually the more common way people use GitHub day to day.) If anything here doesn't match what you're seeing on GitHub's website (their interface changes from time to time), ask on Canvas or in office hours and we'll get it sorted out.

No rush — do this when you're ready. You don't need to create your repository right away. In fact, it makes sense to wait until you know whether you're working solo or with a partner, since that determines your repository name (Step 2) and who needs collaborator access (Step 3). Just have everything set up well before you need to submit a repository link for a course milestone.

Overview

  1. Create a free GitHub account (skip if you already have one).
  2. Create a new private repository for your project.
  3. Add the instructor and TA as collaborators.
  4. Set up the repository structure and clone it to your computer.
  5. Commit and push your work regularly throughout the semester.
  6. Submit the repository link through Canvas.

1Create a GitHub Account

If you don't already have one, go to github.com/signup and create a free account. A free account is all you need for this course — no paid plan required.

  • Use an email address you check regularly; you'll receive collaborator invitations and notifications there.
  • Choose a professional-looking username. This account is worth keeping long-term as part of your professional portfolio, so avoid anything you'll be embarrassed by in a job interview.

2Create a New Private Repository

  1. Once logged in, click the + icon in the top-right corner of GitHub and select New repository.
  2. Repository name: use the course naming convention: 
    fin4414-f26-lastname
    If you're working with a partner, include both last names in alphabetical order, separated by a hyphen: 
    fin4414-f26-lastname1-lastname2

    Example: a student named Priya Shah working individually would name her repository fin4414-f26-shah. A pair, Priya Shah and Alex Diaz, would use fin4414-f26-diaz-shah.

  3. Visibility: select Private. This is required — do not make your project repository public. Your empirical work may involve data (e.g., from WRDS) that cannot legally be redistributed, and a public repository would violate the university's data-licensing agreements.
  4. Check Add a README file.
  5. Under Add .gitignore, select the Python template.
  6. Click Create repository.

Double-check visibility. It's easy to accidentally leave a repository public. After creating it, go to Settings (in your repository) and confirm under Danger Zone that it says "Change repository visibility" with the repo currently Private.

4Structure Your Repository

Model your repository's structure and workflow on the course's public companion repository: github.com/bradleypaye/fin4414 (also linked on Canvas). You don't need to copy it exactly, but a similar structure works well for an empirical finance project:

data/          Small, redistributable example data only (see note below)
notebooks/     Jupyter notebooks with your analysis
python/        Reusable Python modules/functions shared across notebooks
README.md      Explains the repo structure, how to run things, and what
               each file does

Be careful with WRDS-sourced data (CRSP, Compustat, etc.). The real risk is committing raw or lightly filtered records pulled directly from WRDS — e.g., a CSV of security-level daily returns or accounting variables — since that amounts to redistributing the licensed dataset itself, which Virginia Tech's license agreements prohibit regardless of file size. Heavily processed research outputs — summary statistics, regression results, constructed factors or indices, aggregated tables — are the normal contents of a research repository and are fine to commit; they don't let anyone reconstruct the underlying licensed panel. Committing the code that pulls and processes WRDS data (e.g., a script using the wrds Python package) is always fine and keeps your analysis reproducible. If you're unsure whether a specific file crosses the line, ask the instructor or TA before committing it. Small extracts of genuinely public data (e.g., FRED series, or free daily ETF prices from Yahoo Finance) are fine to commit outright. See the "A note on data" section of the companion repo's README for a fuller explanation and examples.

Your README should explain: the repository structure, the order in which notebooks/scripts should be run, required packages, expected inputs, and the outputs produced — enough that the instructor can reproduce your key results by following it.

5Clone the Repository to Your Computer

You'll need Git installed locally. If you'd rather use a graphical tool instead of the command line, GitHub Desktop works well and covers everything below through its interface.

From the command line:

git clone https://github.com/YOUR-USERNAME/fin4414-f26-lastname.git
cd fin4414-f26-lastname

Replace the URL with the one shown on your repository's main page (green <> Code button → HTTPS tab).

6Commit and Push Regularly

As you make progress — cleaning data, writing analysis code, drafting sections of your paper's supporting materials — commit your changes with a short, informative message and push to GitHub:

git add .
git commit -m "Add initial data-cleaning script for CRSP monthly returns"
git push

Per the syllabus, your repository/replication grade reflects how the repository was maintained over the semester, not just its final contents. Commit periodically in logically scoped chunks — after each meaningful step of progress — rather than making one or two massive commits at the end of the semester. A repository history showing only late, last-minute activity will result in a lower repository/replication grade, even if the final code is correct.

If you're new to Git, two good places to start are GitHub's own Git Guides and the Atlassian Git tutorial — both walk through the core commands (clone, add, commit, push, pull) without assuming prior experience.

Use an AI assistant for this — it helps a lot. Figuring out Git purely from documentation can be slow and frustrating. The instructor routinely uses AI coding assistants (e.g., Claude Code) to manage commits, resolve merge conflicts, and untangle Git mistakes, and genuinely recommends doing the same: it can be a real game-changer compared to sorting out Git commands entirely on your own. As with any AI-assisted work, you remain responsible for understanding what happened to your repository and being able to explain it.

7Submit Your Repository Link Through Canvas

At each relevant milestone (and with your final paper), submit the link to your private repository through the Canvas assignment — not by emailing it or posting it anywhere else. Canvas, not GitHub, is the official system of record for course submissions.

Troubleshooting / FAQ

I made my repository public by accident — what do I do?
Go to Settings → Danger Zone → Change visibility and switch it back to Private immediately. If you had already committed any restricted data, also remove it from the file and from the Git history (ask the instructor or TA for help — this is more involved than a normal delete, since old commits still contain the file).
I get "Permission denied" when I try to push.
This usually means Git isn't authenticated with your GitHub account. GitHub no longer accepts your account password for this — you'll need to set up a personal access token or, more simply, install GitHub Desktop and sign in there, which handles authentication for you.
My partner and I both need push access — how do we do that?
If you're working in a pair, add your partner as a collaborator the same way you added the instructor and TA (Step 3), in addition to the instructor and TA. Only one of you needs to create the repository.
Can I use an organization or a different hosting service instead of a personal repository?
Stick with a personal private repository on GitHub.com unless you've discussed an alternative with the instructor in advance.
Do I need a paid GitHub plan for a private repository?
No. GitHub's free plan includes unlimited private repositories with collaborators — this hasn't changed with the retirement of GitHub Classroom.
